# Q3d paper rows: KR96 eps4 0.0123 and 0.0265, and the eps4-definition sensitivity

Protocol version 1, written 2026-11-26 and frozen at the commit that adds it, before any GPU run.
Research diagnostic for the Comput. Mater. Sci. paper (fp32 3D tip selection vs Karma & Rappel
1996). It extends the Q3c result (Option A `w28` plus the Option B four controls at lambda 2.8,
all 5/5 inside the 10% budget against KR96 numerical solvability) from one anisotropy to KR96's
three, and measures how much the anisotropy definition matters. It changes no shader,
coefficient, estimator, metrology, endpoint or reference band.

## Arms (all latticeKinetics on, lambda 2.8 unless noted)

| arm | raw eps4 | change from its row base | grid | est. L40S min |
|---|---:|---|---|---:|
| e171cal | 0.017612992 | eps4 only (dt and grid pinned to `w28`) | 386x386x875 | 95 |
| e265base | 0.0265 | row base | 271x271x613 | 17 |
| e265width | 0.0265 | lambda 2.52 | 301x301x681 | 32 |
| e265dx | 0.0265 | dx 0.6 | 361x361x817 | 72 |
| e123base | 0.0123 | row base | 529x529x1198 | 522 |

- **Sizing rule (self-similar in diffusion units).** For row eps4, r = (V d0/D at 0.0171) / (V d0/D
  at the row), both from KR96 solvability (V d0/D = 2 P^2 sigma*). Box and seed radius scale by r,
  physical terminal time and sample period by r^2. r = 1 reproduces `w28` exactly (model self-test).
  r = 0.7004 for 0.0265 and 1.3693 for 0.0123.
- **dt** = the five-arm `baseDt` rule at the arm's eps4, except `e171cal`, which keeps the `w28` dt so
  only eps4 changes.
- **Why only these controls:** the 0.0265 tip is ~11 cells across at dx 0.8 with the largest interface
  Peclet number (W V/D about 0.055), so width and grid errors are largest there. The 0.0123 tip is the
  best resolved (~33 cells, W V/D about 0.028); its width arm (~15.6 h) is not registered.
- `e171cal` raw eps4 = 0.0171^2 / 0.0166019492, the raw value whose effective (equilibrium-measured)
  anisotropy would equal KR96's grid-corrected 0.0171 if the grid correction is proportional to eps4.

## Gates (per arm)

1. **Execution:** zero page errors, zero GPU device errors, source hashes stable, 9/9 equivalence.
2. **Validity:** terminal schedule complete; operating state ready, stationary and resolved; ahead and
   side clearance >= 8 diffusion lengths (D/V); conservative tip travel >= 6 diffusion lengths.
3. **Reference:** `terminalReferenceAssessment` budget (1+error)(1+uncertainty)(1+drift) - 1 <= 10% in
   P and sigma*, reported separately against the arm's KR96 phase-field and solvability rows.
4. **Row 0.0265 controls:** |change| <= 10% in P, sigma* and V d0/D for `e265width` and `e265dx`
   against `e265base` (the Option B convergence rule).
5. A row is "accepted against X" only if every arm in it passes 1-3 against X and (0.0265) gate 4.

No acceptance consequence follows from `e171cal`; it is a measured sensitivity.

## Frozen prediction for e171cal (not a gate)

Using KR96 solvability slopes d ln y / d ln eps4 around 0.0171 (mean of the two neighbouring
secants: sigma* 1.881, P -0.499) and the measured eps_eff 0.0166019 -> 0.0171:
sigma* 0.06023, P 0.3184, V d0/D 0.012216 (from `w28` 0.05698 / 0.3232 / 0.011901).
A clear miss means the definition effect is not just a change in anisotropy strength (for example
the grid kinetic correction KR96 also applied, or the stiffness error the equilibrium audit found).

## Equilibrium effective anisotropy (diagnostic)

`Q3_EQUILIBRIUM_MATRIX=scripts/research/quant3d-equilibrium-matrix-q3d.json node
scripts/research/quant3d-equilibrium.mjs OUT PORT` measures eps_eff for raw 0.0171 (replicate of the
archived 0.0166019492), 0.0123, 0.0265 and 0.017613 at dx 0.8 R20, dx 0.6 R20 and dx 0.8 R30
(geometries unchanged from the original matrix, lambda 4). Reported beside each row. It selects no
coefficient.

## Execution

- Hardware: AWS g6e (NVIDIA L40S 48 GB), Chrome under xvfb with Vulkan (the `xvfb-vulkan-angle`
  configuration that ran Options A and B). Launcher `scripts/research/aws_q3d_launch.py`.
- Order: preflight (adapter, 9/9 equivalence, VRAM smoke of `e123base`), equilibrium matrix, then
  arms in the table order, then the independent CPU replay (`quant3d-q3c-tip-replay.py`) of every
  checkpoint.
- Caps: user-data `shutdown -h` hard stop at min(18 h, floor($35 / hourly rate)) (18 h, about $33.5, on
  g6e.xlarge); the rows run gets the cap minus 90 min; after the remote finishes it waits at most 3 h
  for the local pull and then shuts itself down; instance-initiated shutdown terminates the instance.
- Estimated 12.3 GPU-hours (throughput interpolated from the Option A/B runs), about $25 at the
  g6e.xlarge on-demand rate. Spend cap $35.
- An invalid or failed arm is recorded and the remaining arms still run; a device error stops the
  campaign.

## Not in this protocol

The fp64 cross-check (`scripts/research/quant3d-fp64-port.*`, a separate session), any width arm for
0.0123, a calibrated dx 0.6 arm at 0.0171, and any change of the published Q3c numbers.
